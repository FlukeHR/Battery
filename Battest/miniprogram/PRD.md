# 电检通微信小程序 PRD

> 版本：V0.1 讨论稿
>
> 阶段：V0.1 MVP 已实现，待开发者工具与真机验收
>
> 核心假设：微信原生、个人车主、免登录、复用现有预测 API

## 1. 产品定位

电检通小程序帮助两轮电动车车主在没有专业检测仪器时，根据电池规格、使用年限、充电习惯和环境，快速获得电池健康度（SOH）、预计剩余寿命、风险因素及保养建议。

产品提供“可解释的初步筛查”，不宣称检测真实容量，也不替代维修机构、厂商质保或安全鉴定。

## 2. 目标用户与场景

### 核心用户

- 已使用电动车 6 个月以上，开始关注续航衰减的个人车主。
- 准备购买或出售二手电动车，希望减少电池信息差的用户。

### 核心场景

1. **日常体检**：用户想知道电池是否处于正常衰减区间、何时需要重点检查。
2. **续航异常**：近期续航缩短，用户希望判断高温、深度放电、重载或激烈驾驶是否为主要因素。
3. **二手交易**：买卖双方现场共同填写信息，生成一份可分享但明确标注“非专业检测”的报告。
4. **保养提醒（P1）**：根据上次评估结果，在合适时间提醒重新评估或线下检测。

## 3. 产品目标与非目标

### V0.1 目标

- 新用户在 3 分钟内完成一次评估。
- 用通俗语言解释结果，而不只展示单个分数。
- 网络异常时保留输入并提供明确的重试入口。
- 用户无需登录即可查看最近 20 份本机报告。

### 暂不包含

- 不连接车辆 BMS、蓝牙设备或维修仪器。
- 不通过照片或 OCR 自动识别电池铭牌。
- 不提供二手车价格、维修店推荐、交易担保或付费服务。
- 不把规则估算包装成已加载的机器学习实测模型。
- 不采集手机号、微信头像、精确位置或通讯录。

## 4. 信息架构

底部导航建议保留三个入口：

1. **评估**：场景选择、分步填写、提交预测。
2. **记录**：本机历史报告、查看、删除、再次评估。
3. **关于**：方法说明、数据说明、免责声明、反馈入口。

评估流程：

```text
选择场景 → 电池信息 → 充电习惯 → 使用环境 → 确认 → 结果报告
```

## 5. 功能需求

### P0：评估流程

- 首页直接提供“开始评估”，并展示预计耗时和使用边界。
- 选择日常体检、续航异常或二手交易场景；场景只影响引导文案，不改变算法。
- 分步采集以下 12 个字段，并提供“不确定”或常见值：
  - 电池类型、额定电压、标称容量、已使用月份；
  - 常用充电起止电量、每周充电次数；
  - 驾驶习惯、负载情况、长期存放频率、所在城市、停放环境。
- 在本地校验数值范围，充电结束电量必须高于开始电量。
- 提交时显示单一加载状态，10 秒超时；失败后可以原样重试。

### P0：结果报告

- 首屏展示 SOH 百分比、低/中/高风险和预计剩余月数。
- 分区展示主要衰减因素、逐条保养建议、评估依据摘要。
- 明确显示算法版本、生成时间和“辅助评估”免责声明。
- 支持保存到本机、重新评估和分享摘要卡片。
- 分享内容不得携带完整原始输入，只展示风险等级、建议摘要和小程序入口。

### P0：历史记录

- 本机最多保存 20 份报告，按生成时间倒序排列。
- 支持查看、单条删除和清空全部记录。
- 卸载微信、清理缓存或更换设备后记录可能丢失，界面需提前说明。

### P1：后续能力

- 可选微信登录及跨设备同步。
- 同一电池的趋势曲线与复测提醒。
- 铭牌 OCR、车型/电池型号库、维修点合作入口。
- 经用户同意后的匿名产品分析事件。

## 6. API 契约

MVP 调用 `POST https://battest.ccwu.cc/api/predict`，字段与网站保持一致。响应必须包含：

- `soh_percent`
- `estimated_remaining_months`
- `risk_level`
- `main_degradation_factors`
- `suggestions`
- `model_used`

兼容扩展字段：`battery_chemistry`（电池化学类型）、`training_datasets`（实际训练来源）、`prediction_note`（估算方式说明）和 `algorithm_version`（算法版本）。新接口按类型使用 CALB 三元锂模型或 HUST + MATR 磷酸铁锂模型；铅酸及不确定类型仍为规则估算。小程序展示接口返回的数据来源，不复制模型。

正式发布前建议增加版本化端点 `/api/v1/predictions`，并补充 `request_id`、`algorithm_version`、`generated_at`。小程序只依赖公开响应字段，不直接依赖 `mapped_features` 内部实现。

## 7. 状态与异常

- 无网络：保留草稿，提示联网后重试。
- 接口超时：10 秒后结束加载，不自动重复提交。
- 输入无效：定位到具体步骤和字段，不清空已填内容。
- 服务不可用：展示统一错误编号和网页备用入口。
- 结果低于安全阈值：建议尽快线下检测，不使用“立即报废”等绝对结论。

## 8. 验收标准

- 主流 iOS、Android 微信客户端可完成全流程，无横向滚动或遮挡。
- P0 字段与网站 API 契约一致，典型输入的结果与网页一致。
- 首页到结果页的核心路径不超过 6 次主要操作。
- 连续点击提交不会产生并发重复请求。
- 失败重试、历史删除、清空记录和分享入口均有可验证反馈。
- 提审前完成隐私保护指引、服务器域名、免责声明和真机网络测试。

## 9. 成功指标

内测阶段先通过 20–30 名目标用户的任务测试衡量：

- 评估完成率 ≥ 80%。
- 首次评估中位耗时 ≤ 3 分钟。
- 结果理解正确率 ≥ 80%。
- “建议对我有帮助”评分 ≥ 4/5。
- 严重错误率为 0，预测接口成功率 ≥ 99%。

## 10. 待确认决策

1. 首版是否只面向两轮电动车，还是同时覆盖电动汽车和储能电池？
2. 小程序主体是个人、学校还是企业，AppID 是否已经申请？
3. 是否坚持免登录、本机历史，还是首版就需要微信登录与云端同步？
4. 二手交易场景是否是首版重点，是否需要可验证的报告编号？
5. 是否计划未来发布支付宝/H5；若确定跨端，应重新评估 Taro。
6. 当前域名是否已完成可用于小程序的备案，并能在微信后台配置为 request 合法域名？
